# Решения (вопрос → решение → почему)

1. **Чем читать Excel?** → `openpyxl` напрямую, без pandas. → Нужен точный контроль над
   типами ячеек (datetime vs текст vs число), pandas приводит смешанные колонки к object/float
   и теряет различие «текст "5"» / «число 5». Меньше зависимостей.

2. **Как считать «с полной точностью»?** → `decimal.Decimal`; float из ячейки переводится через
   `Decimal(str(x))` (0.15 → `Decimal("0.15")`). Округление — `ROUND_HALF_UP` до 2 знаков только
   в `summary.json`/отчёте. → Нет накопления двоичной ошибки float, «бухгалтерское» округление.

3. **`quantity` — текст `"5"` допустим?** → Нет, пропуск. Принимаются только числовые ячейки с
   целым значением (`3.0` → 3; `2.5` → пропуск). → ТЗ прямо перечисляет «текст» среди невалидных;
   в данных встречается только `"n/a"`. bool не считается числом.

4. **`unit_price` с разделителями тысяч (`"1 234,50"`, `"1.234,50"`)?** → Пропуск. → ТЗ разрешает
   только один десятичный разделитель; угадывать формат рискованно.

5. **`discount` вне [0, 1] (например 1.5, `"150%"`) или нераспознаваемый текст?** → Строка
   пропускается. Текст без `%` (`"0,2"`) трактуется как доля. → ТЗ задаёт диапазон доли; молча
   обнулять скидку значило бы завышать выручку.

6. **Дата Excel в виде числа (серийный номер)?** → Принимается через
   `openpyxl.utils.datetime.from_excel`. → Это тоже «дата Excel», если ячейке не задан формат даты.

7. **Пустые `order_id`, `region`, `category`, `product` в непустой строке?** → Пропуск с причиной
   «пустое поле …». `manager` не обязателен (в агрегатах не участвует). Пустой `order_id` не
   участвует в поиске дубликатов. → Без этих полей строку нельзя корректно агрегировать.

8. **Как определяется дубликат?** → По `order_id` после обрезки пробелов; первое вхождение
   «занимает» id ещё до валидации (правило 2: «даже если оно окажется невалидным»).

9. **Что такое «полностью пустая строка»?** → Все 9 колонок `None` или строки из пробелов.

10. **Несколько ошибок в строке?** → Строка считается один раз, в `reason` все причины через `; `.
    → Удобнее исправлять источник.

11. **Номер строки в логах?** → Номер строки Excel (заголовок = 1, первая строка данных = 2).

12. **Куда логировать пропуски?** → И в stderr (WARNING на каждую строку, `-q` отключает), и в
    `out/skipped.csv` (всегда). → ТЗ допускает любой вариант; CSV удобен для разбора, stderr — для
    наглядности.

13. **`plan_vs_fact` — какие регионы и год?** → Объединение регионов из продаж и из плана;
    `target` — сумма всех месяцев листа `Targets` по региону, `fact` — вся выручка региона
    (в данных один год, 2025). Если плана нет/он 0 → `completion_pct: null`. Регионы плана тоже
    обрезаются по краям. → Не теряем регионы ни с одной стороны и не делим на ноль.

14. **Некорректная строка в `Targets`?** → Фатальная ошибка с номером строки (код 2). → План —
    справочник; молча пропускать его строки значит искажать % выполнения.

15. **Сортировка `revenue_by_*` и порядок ключей верхнего уровня?** → Словари отсортированы по
    ключу (Unicode-порядок, для кириллицы совпадает с алфавитным, «ё» в данных нет); ключи
    верхнего уровня — в порядке из ТЗ.

16. **Графики: формат чисел и валюта?** → Разделитель тысяч — неразрывный пробел (`1 234 567`),
    десятичная запятая, подписи «руб.» (вместо «₽» — гарантированно есть в шрифте DejaVu Sans).
    Мелкие доли (< 4 %) на кольцевой диаграмме подписаны только в легенде (иначе текст
    наезжает). matplotlib через объектный API (`Figure`) без `pyplot` — нет глобального
    состояния и GUI-бэкенда.

17. **Линтер.** → `ruff check` + `ruff format` + `mypy --strict`. Отключены `RUF001/002/003`
    («похожие» символы): они срабатывают на любой русский текст и в этом проекте — шум.
