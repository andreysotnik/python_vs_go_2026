# Решения (вопрос → решение → почему)

1. **Cron-библиотека или свой парсер?** → Свой строгий парсер 5 полей (`cron.py`, ~130 строк).
   Почему: задача «срабатывает ли в эту минуту» — простая проверка совпадения полей; меньше зависимостей,
   полный контроль над валидацией и семантикой DOM/DOW (OR, как в Vixie cron). Макросы `@daily` и т.п. не поддерживаются — ТЗ требует 5 полей.
2. **В какой таймзоне сравнивать cron?** → Слот `--at`/текущая минута переводится в таймзону задачи и сравнивается по местному времени.
   DST: несуществующее время не срабатывает, повторяющееся — только в первый проход (fold=0). Почему: предсказуемо, без дублей.
3. **Ключ дедупликации** → `(job name, минута в UTC)`; маркер-файл `STATE_DIR/sent/<job>/<YYYYMMDDTHHMMZ>.json`.
   Почему: один и тот же момент, записанный с разными смещениями/секундами, даёт один ключ. Имя задачи ограничено `[A-Za-z0-9._-]`, чтобы безопасно быть именем каталога.
4. **Когда ставить маркер?** → После успешного SMTP-ответа на DATA, атомарно (tmp+fsync+rename+fsync каталога), под `flock` на задачу.
   Почему: неуспешная отправка не «съедает» слот; flock защищает от гонки демона и ручного `once`. Остаточный риск: падение ровно между 250 OK и rename → один дубль (at-least-once) — честно задокументировано.
5. **Классификация ошибок SMTP** → 4xx, обрыв соединения, таймаут, сетевые OSError — временные; 5xx, SMTPNotSupported (нет STARTTLS), ошибка проверки сертификата, прочие исключения — постоянные.
   `SMTPRecipientsRefused` постоянна, только если все отказы 5xx. Повторы: 3 попытки, задержка 1 с·2^(n-1) (1 с, 2 с) — укладывается в 10 с `docker stop` по умолчанию.
6. **SIGTERM во время отправки** → Обработчик только ставит флаг; текущее письмо (с его повторами) дописывается, оставшиеся задачи того же слота не отправляются и логируются (`aborted`). Почему: так сформулировано ТЗ («дождаться текущего письма»); `stop_grace_period: 30s` в compose с запасом.
7. **Пропущенные слоты** → Демон хранит `STATE_DIR/last_tick`; при старте и при «пересыпании» (сон хоста, скачок часов, долгая отправка) логирует каждый пропущенный due-слот (WARNING), но не отправляет. Окно сканирования ограничено 7 днями. Демон, запущенный в 09:00:30, первым обрабатывает слот 09:01; слот 09:00 считается пропущенным.
8. **`--at` без смещения** → Ошибка (код 2). Почему: неоднозначно, а `once` используется в тестах/ручном запуске. `Z` принимается.
9. **Относительные пути вложений** → От каталога `jobs.yaml`, а не от CWD. Почему: конфиг переносим (в Docker монтируется в `/app/config`).
10. **Валидация адресов** → Прагматичная регулярка (`local@domain.tld`), поддерживается форма `Имя <addr>`, запрещены CR/LF (защита от инъекции заголовков). Полный RFC 5322 не реализуем.
11. **Кодировка тела** → `Content-Transfer-Encoding: base64`, charset utf-8. Почему: сообщение 7-bit чистое, работает и с серверами без 8BITMIME. Subject кодируется по RFC 2047 стандартной библиотекой (`email.policy.SMTP`).
12. **SMTP-переменные при `validate`** → Не проверяются: `validate` проверяет конфиг (по ТЗ). `once`/`run` проверяют SMTP-окружение сразу при старте (fail fast, код 2).
13. **Значения по умолчанию** → `SMTP_TLS=starttls` (безопасный дефолт), порт по режиму (25/587/465), `STATE_DIR=./state`, таймаут SMTP 30 с (`SMTP_TIMEOUT`).
14. **Коды выхода** → 0 — успех (в т.ч. «нечего отправлять» и «уже отправлено»), 1 — хотя бы одна задача не отправлена, 2 — ошибка конфигурации/окружения/аргументов.
15. **Зависимости в Docker** → PyPI изнутри Docker-сборки оказался доступен (проверено `pip download` в `python:3.12-slim-bookworm`), поэтому вендоринг колёс не понадобился. Зависимости ставятся из `requirements.lock` (экспорт `uv.lock`) с `--require-hashes`. Строка `# syntax=docker/dockerfile:1` убрана — её загрузка с docker.io падала по таймауту TLS, а встроенного frontend достаточно.
16. **Базовый образ и Mailpit** → `python:3.12-slim-bookworm` (уже был локально — не качали лишнего), `axllent/mailpit:v1.27` (закреплённый тег вместо `latest`). `tzdata` добавлен как pip-зависимость, чтобы таймзоны не зависели от системного пакета.
17. **Линтер** → `ruff check` (наборы E,F,W,I,B,UP,SIM,RUF,N,S,PL) + `ruff format`. Одна точечная `noqa: PLR0911` на `classify()` — плоская таблица соответствий читабельнее, чем искусственное дробление.
18. **Фейковый SMTP в интеграционных тестах** → `aiosmtpd` (dev-зависимость) в том же процессе, на свободном порту; проверяются конверт (получатели To+Cc), декодированная кириллическая тема и её RFC 2047-вид на проводе, тело, вложение побайтно, повтор при 451 и отсутствие повтора при 554.
19. **Очистка старых маркеров** → Не реализована (файл ~150 байт на отправку). Можно чистить `find $STATE_DIR/sent -mtime +90 -delete`.
