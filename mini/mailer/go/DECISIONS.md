# Решения

| Вопрос | Решение | Почему |
|---|---|---|
| Свой cron-парсер или библиотека? | `github.com/robfig/cron/v3` (только парсер, 5 полей, без `@every`/секунд); проверка «срабатывает в минуту T» = `Next(T-1s) == T` в таймзоне задачи | Зрелая библиотека, корректно обрабатывает DST; свой парсер — лишний риск. Сам планировщик robfig не используем: нужен контроль над дедупликацией и пропусками |
| YAML | `gopkg.in/yaml.v3` с `KnownFields(true)` | Опечатка в поле (`shedule`) должна быть ошибкой `validate`, а не молча игнорироваться |
| Относительные пути вложений | Относительно каталога `jobs.yaml` | Не зависит от рабочего каталога процесса (важно в Docker) |
| Пустой `timezone` | UTC | Явное и предсказуемое поведение |
| Формат `{{datetime}}` | `YYYY-MM-DD HH:MM ±HH:MM` в таймзоне задачи | В ТЗ не задан; со смещением однозначно, аббревиатуры зон (MSK/+03) непоследовательны |
| SMTP-клиент | stdlib `net/smtp` + свой `tls.Dialer` для `SMTP_TLS=tls` | Без внешних зависимостей; `net/smtp` заморожен, но для отправки достаточен |
| Что повторять | 4xx, сетевые ошибки, EOF, таймаут — временные; 5xx, ошибки сертификата, нет STARTTLS/AUTH, прочее — постоянные | ТЗ: «5xx не повторять»; неизвестные ошибки безопаснее не повторять |
| Задержки повторов | 3 попытки, 1 с → 2 с (×2, кап 30 с), без jitter | ТЗ: 3 попытки с экспоненциальной задержкой; одна рассылка — jitter не нужен |
| Один отказавший получатель (RCPT 5xx) | Всё письмо — постоянная ошибка | Простая и предсказуемая семантика; частичная доставка усложнила бы дедупликацию |
| Формат состояния | Файл-маркер на (job, слот UTC) с атомарной записью + `last_tick` | Без БД; атомарность rename; слот в UTC → один и тот же момент в разных `--at`-смещениях = один слот |
| Когда писать маркер | После успешной отправки | Иначе сбой отправки «съел» бы письмо. Окно «отправлено, но маркер не записан» (крах между) — минимально и логируется |
| Неудачная задача | Не помечается; демон не повторяет её в следующие минуты; можно дослать `once --at` | ТЗ: пропущенное не досылается автоматически |
| Текущая минута при старте демона | Обрабатывается (с дедупликацией) | Это не простой: процесс уже работает в эту минуту; дедупликация исключает дубль |
| Учёт пропусков | `last_tick` в STATE_DIR; слоты между ним и текущей минутой логируются WARN (до 50 на задачу + итог) | ТЗ: «не досылаются, только логируются»; кап защищает от лавины логов после долгого простоя |
| SIGTERM во время отправки | Текущее письмо (включая повторы) завершается через `context.WithoutCancel`, новые задачи не стартуют; повторный сигнал — немедленный выход; `stop_grace_period: 90s` | ТЗ: «дождаться отправки текущего письма»; худший случай 3×30 с таймаута укладывается |
| `once` без `--at` | Текущее время | Удобно для ручного запуска; в ТЗ `--at` показан в примере |
| Коды выхода | 0 ок, 1 — не отправлена хотя бы одна задача, 2 — ошибка конфигурации/окружения/аргументов | Различимо для скриптов и CI |
| Message-ID | `<unixnano.random@домен-отправителя>`, одинаковый для всех попыток одного письма | Уникальность + получатель может склеить повторы |
| Логи `validate` | Человекочитаемые (stdout/stderr), остальное — JSON | `validate` — команда для человека; «понятные ошибки» |
| Docker: сеть при сборке | Зависимости завендорены (`vendor/`, `-mod=vendor`), `GOTOOLCHAIN=local`; убрана строка `# syntax=docker/dockerfile:1` | Docker Hub отвечал таймаутом на загрузку frontend-образа; без сети сборка воспроизводима |
| Базовые образы | `golang:1.26-alpine` (уже был локально) и `distroless/static-debian12:nonroot` (уже был локально); `go 1.25` в go.mod | Диск Docker почти заполнен — не скачивать лишнего; go1.27 образа локально нет |
| Таймзоны в образе | `import _ "time/tzdata"` | Бинарь не зависит от tzdata в образе |
| Версия Mailpit | `axllent/mailpit:v1.21.8` (закреплена) | Воспроизводимость вместо `latest` |
| Линтер | `gofmt`, `go vet`, `staticcheck` 2026.2.2 (установлен в `./.bin`, не в систему); golangci-lint не установлен | Стандартный набор Go без глобальных установок |
