Ты — senior-разработчик. Напиши на Go (локально go1.27.3) сервис, который отправляет email-рассылки по расписанию. Код должен быть промышленного качества: надёжный, покрытый тестами, готовый к запуску в Docker.

## Конфигурация
Файл расписания `jobs.yaml` (путь передаётся флагом `--config`):
```yaml
jobs:
  - name: daily-report
    schedule: "0 9 * * 1-5"        # cron, 5 полей
    timezone: "Europe/Moscow"
    to: ["team@example.com", "boss@example.com"]
    cc: []
    subject: "Ежедневный отчёт за {{date}}"
    body: |
      Привет! Отчёт за {{date}} во вложении.
    html: false
    attachments: ["./files/report.pdf"]   # необязательно
```
- Шаблоны в `subject` и `body`: `{{date}}` (YYYY-MM-DD в таймзоне задачи), `{{datetime}}`, `{{job}}`.
- SMTP задаётся через переменные окружения: `SMTP_HOST`, `SMTP_PORT`, `SMTP_USER`, `SMTP_PASSWORD` (необязательно), `SMTP_FROM`, `SMTP_TLS=none|starttls|tls`.
- Каталог состояния задаётся через `STATE_DIR`.

## Команды CLI
- `validate --config jobs.yaml` — проверить конфиг: синтаксис cron, таймзоны, адреса, существование вложений. Код выхода ≠ 0 и понятные ошибки, если что-то не так.
- `once --config jobs.yaml --at 2026-11-19T09:00:00+03:00` — отправить все задачи, которые по расписанию должны сработать в эту минуту, и выйти. Нужно для тестов и ручного запуска.
- `run --config jobs.yaml` — демон: срабатывает в начале каждой минуты по расписанию.

## Требования к надёжности
- Тело письма в UTF-8, корректные заголовки (Subject с кириллицей кодируется по RFC 2047), Message-ID, Date.
- Повторы при временных ошибках SMTP: 3 попытки с экспоненциальной задержкой. Постоянные ошибки (5xx) не повторять.
- Нет дублей при перезапуске: состояние «задача X отправлена за слот T» хранится в `STATE_DIR`. Повторный `once` с тем же `--at` не отправляет письмо второй раз.
- Корректное завершение по SIGTERM/SIGINT: дождаться отправки текущего письма.
- Задачи, пропущенные во время простоя, не досылаются (только логируются).
- Структурные логи (JSON) в stdout.

## Поставка
- `Dockerfile` (multi-stage, non-root) и `docker-compose.yml` с сервисом рассылки и Mailpit (`axllent/mailpit`) для локальной проверки. Используй порты хоста 21025 (SMTP Mailpit) и 28025 (UI/API Mailpit) и compose project name `mini_mailer_go`.
- Тесты: модульные (cron/таймзоны, шаблоны, повторы, дедупликация) и интеграционный с фейковым SMTP-сервером внутри теста (без Docker), который проверяет полученные письма: получателей, тему с кириллицей и вложение.
- Линтер или форматтер языка без замечаний.
- `README.md`: запуск, конфиг, примеры.

## Порядок работы
Реализуй → тесты и линтер → `docker compose up --build`, отправь письмо через `once` в Mailpit и проверь через API Mailpit, что оно пришло → `docker compose down`.
