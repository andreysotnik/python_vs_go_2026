# Решения

| Вопрос | Решение | Почему |
|---|---|---|
| Lookahead/lookbehind в Go `regexp` (RE2) нет — как отсекать «застрахуй», «учебник»? | Правила применяются к целому нормализованному слову; позиция корня задаётся якорем `^` + список приставок, плюс точечные исключения (`excl`). | Работает в RE2, линейное время, явно контролирует, где может стоять корень. |
| Что считать `word`/`start`/`end` в match? | Всё слово-токен (или склеенное окно `х у й`), смещения в **рунах** (code points), `end` не включается. | Цензура заменяет слово целиком; руны совпадают с индексами символов в Python/JS, удобнее для сравнения. |
| Формат `censor` | Первая буква оригинала + `***` (`пиздец` → `п***`, `x у й` → `x***`). | Прямо по ТЗ («*** с сохранением первой буквы»). |
| Гомоглиф vs транслит (`p`→`р` или `п`, `h`→`н` или `х`, `y`→`у` или `й`) | Для слов со смешением письменностей проверяются оба варианта: визуальный (по ТЗ: h→н, b→в, y→у) и транслит. `B` заглавная → `в`, `b` строчная → `б`. | Один вариант всегда теряет часть случаев (`pизда` vs `xyй`). |
| Чисто латинские слова: переводить в кириллицу? | Нет. Для них — отдельные строгие латинские правила транслита. | Иначе `hue`→«хуе», `ebay`→«ебау», `ebook`, `EBITDA` давали бы ложные срабатывания. |
| Цифра `3` в латинице | Проверяются оба варианта: `3→e` (`sh3t`) и `3→z` (`pi3da`). | Неоднозначность реальна, вариантов всего два. |
| `*` внутри слова | Два толкования: разделитель (`х*у*й`) и одна скрытая буква из короткого списка (`п*здец`, `f*ck`). Если звёздочек > 2 — только разделитель. | `х***` — это уже зацензуренный текст, а не маскировка. |
| Повторы букв | Схлопываются до одной (`бляяяять`, `ббббля`); правила пишутся под схлопнутую форму (`ебанный`→`ебаный`). | Проще, чем `+` после каждой буквы. Побочный эффект `shiitake`→`shitake` закрыт исключением. |
| Разделители между буквами | «Окно» соседних токенов через 1–3 символа `пробел . - _ + ~ / \ | ' "`; внутри только одиночные буквы, по краям фрагменты ≤3 букв; минимум 3 буквы. Запятая — не разделитель. | Ловит `х у й`, `п-и-з-д-а`, `ху й`, не склеивая обычные слова (`за лупой`). |
| `U.S. hit` → `ushit`, `it's hit` → `shit` | Английские правила в окне — только если все фрагменты ≤2 букв; апостроф внутри слова не рвёт токен. | Иначе типичный английский текст давал ложные срабатывания. |
| Граница окна справа (`x у й с ним`, `п-и-з-д-а`) | Окно сужается слева до минимального совпадения и расширяется вправо по одиночным буквам, но не через отдельно стоящий предлог/союз (а, в, и, к, о, с, у, я), если он отделён пробелом. | Цензура `x у й с ним` → `x*** с ним`, а `п-и-з-д-а` закрывается целиком. |
| Корень «хуй» и приставка «у» | «у» не входит в список приставок для «хуй». | `с`+`у`+`хую` = «сухую». |
| «Ебург», «ебонит» | «ебонит» — исключение; «Ебург» оставлен матом. | «Ебург» — грубый сленг с явным корнем; «ебонит» — частая ошибка в слове «эбонит». |
| Слова вне списка ТЗ (сука, херня, гандон) | Не ловятся. | ТЗ задаёт перечень корней; расширение снижает предсказуемость точности. |
| Линтер | `gofmt`, `go vet`, `staticcheck` 2026.2.2 (через `go run`, без добавления в go.mod). | Стандартный набор для Go; golangci-lint локально не установлен. |
| Замер производительности | Подкоманда `bench` (100 000 вызовов `Check` на смеси строк) + замер `check --input` на файле в 100 000 строк + `go test -bench`. | Воспроизводимо одной командой. |
