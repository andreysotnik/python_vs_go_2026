# profanity — фильтр нецензурной лексики на регулярных выражениях (Go)

Библиотека и CLI: находят русский мат (корни хуй/пизд/еб/бля/мудак/пидор/залуп
во всех формах) и базовый английский (fuck, shit, bitch, cunt, motherfucker,
bullshit), устойчиво к маскировке. Без ML и внешних API, только стандартная
библиотека Go (`regexp`, RE2).

## Запуск

Требуется Go ≥ 1.25 (проверено на go1.27.3), внешних зависимостей нет.
Все команды — из каталога проекта (где лежит `go.mod`).

Проверка файла (одна строка входа → одна строка JSONL):

```sh
go run ./cmd/profanity check --input data/sample.tsv
```

Остальное:

```sh
echo 'Не еби мозг' | go run ./cmd/profanity check          # stdin вместо --input
echo 'Полный пиздец, x у й с ним' | go run ./cmd/profanity censor
go run ./cmd/profanity eval --input data/sample.tsv        # precision / recall / F1 + ошибки
go run ./cmd/profanity eval --input testdata/hard.tsv      # свои 66 трудных примеров
go run ./cmd/profanity bench --lines 100000                # замер строк/с
go build -o profanity ./cmd/profanity                      # бинарник, если нужен
```

Тесты и линтеры:

```sh
go test ./...
gofmt -l . && go vet ./...
env -u HTTPS_PROXY -u HTTP_PROXY GOPROXY=https://proxy.golang.org,direct \
  go run honnef.co/go/tools/cmd/staticcheck@latest ./...
```

## Примеры

```
$ printf 'Нахуя ты это сделал?\nНаша команда лучшая\nп-и-з-д-а рулю\n' | go run ./cmd/profanity check
{"line":1,"text":"Нахуя ты это сделал?","profane":true,"matches":["Нахуя"]}
{"line":2,"text":"Наша команда лучшая","profane":false,"matches":[]}
{"line":3,"text":"п-и-з-д-а рулю","profane":true,"matches":["п-и-з-д-а"]}

$ echo 'Полный пиздец, x у й с ним, f*ck' | go run ./cmd/profanity censor
Полный п***, x*** с ним, f***
```

Библиотека (`profanity/profanity`):

```go
res := profanity.Check("ну ёб твою, хуйня")
// res.Profane == true
// res.Matches == [{Word:"ёб" Start:3 End:5 Root:"еб"} {Word:"хуйня" Start:12 End:17 Root:"хуй"}]
profanity.Censor("Бля, опоздал") // "Б***, опоздал"
```

`Start`/`End` — смещения в символах (rune), `End` не включается. В JSON:
`{"profane": bool, "matches": [{"word","start","end","root"}]}`.

## Подход

1. **Токенизация.** Слово — последовательность букв, цифр и символов `@ $ *`
   (плюс `}{` как «х» и апостроф внутри слова: `let's`, `под'ебка`).
2. **Варианты нормализации токена** (все регулярки скомпилированы один раз, на уровне пакета):
   - кириллица по визуальному сходству: `x→х, y→у, e→е, o→о, a→а, p→р, c→с, k→к, m→м, h→н, B→в, b→б, u→и, n→п`,
     цифры/символы `0→о, 3→з, 6→б, 1→и, 4→ч, @→а, $→с`;
   - транслитерация для смешанных слов: `p→п, z→з, h→х, ya→я, sh→ш…` (`pизда`, `hуй`);
   - латиница для английских корней: `1→i, 3→e, 0→o, $→s, @→a`, кириллические двойники → латиница (`fуck`);
   - `*` внутри слова — либо разделитель (`х*у*й`), либо одна скрытая буква (`п*здец`, `f*ck`);
   - нижний регистр, `ё→е`, схлопывание повторов (`бляяяять→блять`, `ббббля→бля`).
3. **Правила по корням** применяются к **целому слову**, поэтому позиция корня
   контролируется: «хуй», «еб», «бля», «пидор» допускаются только в начале слова
   или после списка приставок (`на|по|за|от|вы|съ|объ|долбо…`), «пизд» и «залуп» — где угодно.
   Так отсекаются «застрахуй», «тихую/сухую», «учебник», «потребитель», «рубля»,
   «оскорблять», «скипидар», «Scunthorpe» (cunt — только с начала слова),
   а «shiitake»/«Matsushita» — отдельными исключениями.
4. **Чисто латинские слова** проверяются английскими правилами и строгими правилами
   транслита (`pizdec`, `blyat`, `nahuy`, `zaebal`), специально не срабатывающими на
   `hue`, `ebay`, `ebook`, `EBITDA`, `spider`, `mudra`, `pizza`.
5. **Разделители между буквами** (`х у й`, `х.у.й`, `п-и-з-д-а`, `ху й`): соседние
   токены, между которыми 1–3 символа из `пробел . - _ + ~ / \ | ' "`, склеиваются в
   «окно» — внутри окна только одиночные буквы, по краям допустимы фрагменты до 3 букв.
   Найденное окно сужается слева и расширяется вправо (но не через отдельно стоящие
   предлоги при пробеле: `x у й с ним` → цензура только `x у й`). Если в окне есть
   фрагмент длиннее 2 букв, английские правила не применяются (`U.S. hit` ≠ `ushit`).

## Качество

| набор | примеров | precision | recall | F1 |
|---|---|---|---|---|
| `data/sample.tsv` | 20 | 1.0000 | 1.0000 | 1.0000 |
| `testdata/hard.tsv` (свои трудные) | 66 (32 мат / 34 ловушки) | 1.0000 | 1.0000 | 1.0000 |

Свои примеры писались до прогона и вскрыли несколько проблем (см. `WORKLOG.md`);
на скрытой выборке ожидаемо будет ниже 1.0.

## Производительность

Apple Silicon (arm64), go1.27.3, один поток:

- `go run ./cmd/profanity bench --lines 100000` (смесь 16 строк по 50–60 символов,
  половина с матом): **~113 000 строк/с** (100 000 строк за ~0.88 с, три прогона 111–116 тыс.);
- `check --input` по файлу из 100 000 строк (примеры из `hard.tsv`/`sample.tsv`), включая
  чтение и JSON-вывод: 0.45 с → **~220 000 строк/с**;
- `go test -bench . ./profanity`: ~9.2 мкс на строку.

## Ограничения

- Только перечисленные в ТЗ корни: «сука», «херня», «гандон», «шлюха» и т. п. не ловятся намеренно.
- Пробелы внутри длинных частей слова не склеиваются: `пиз да`, `по ху й` (ловится только `ху й`).
- Разбор окна эвристический: `х у я к` → цензурится `х у я`, «к» остаётся.
- Транслит ловится только для типичных написаний; экзотика (`bl'ad`, `xyu`, `p!zda`) — нет.
- `Ебург` (сленг) считается матом; инициалы с короткой фамилией дают ложное срабатывание (`Е.Б. Ким` → «ебким»; с фамилией длиннее 3 букв — нет).
- Морфологии нет: решение «корень + позиция + исключения», новые слова-ловушки требуют правки правил.
