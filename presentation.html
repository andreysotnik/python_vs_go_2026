Мини-задачи: что повлияло

Разницу делает не язык как таковой, а готовые библиотеки под задачу.

📊 Excel: Python в 3,3 раза быстрее и в 3 раза дешевле

  • openpyxl и matplotlib закрыли задачу «из коробки»: 29 вызовов инструментов, 6,7 минуты
  • В gonum/plot нет кольцевой диаграммы, Go-агент рисовал её сам. Ещё была паника на пустых данных и ручная вёрстка подписей: 67 вызовов
  • Минус Go из-за окружения: локальный golangci-lint несовместим с go1.27

✉️ Рассылка: паритет · 🤬 Мат-фильтр: Go чуть точнее

  • Оба сервиса прошли 11/11 проверок. Go-агент нашёл у себя гонку благодаря go test -race
  • В regexp Go (RE2) нет lookahead/lookbehind, поэтому агент проверял слово целиком. Всё равно поймал «бл@ть», которое пропустил Python
  • Скорость фильтра: Go ~220 тыс. строк/с, Python ~75 тыс. Оба ошиблись на «Ебенезер Скрудж»

Что говорят исследования: за Go

Где Python уступает: ошибки, которые компилятор Go ловит до запуска, и проблемы экосистемы.

Типы ловят основные ошибки LLM

94% ошибок компиляции в коде от LLM — провалы проверки типов (PLDI 2025, на TypeScript). В Python такие ошибки проявляются только во время выполнения.
Type-Constrained Code Generation · GitHub Octoverse 2025

Компилятор как страховочная сетка

Google: статическая типизация Go — «автоматическая страховочная сетка для агентного кода», а выдуманное поле структуры отвергается сразу. Плюс быстрая сборка, gofmt и «один способ сделать».
Google Developers Blog · Bruin

Устаревшие API в Python-библиотеках

Модели используют устаревшие API в 25–38% случаев на 8 популярных библиотеках (ICSE 2025). Без документации исполняется лишь 42,6% кода под нужную версию библиотеки. Гарантия совместимости Go 1 эту проблему смягчает (наш вывод).
ICSE 2025 · arXiv 2604.09515

Выдуманные пакеты и развёртывание

19,7% пакетов, которые рекомендуют модели, не существуют (USENIX Security 2025, Python и JS). Злоумышленники регистрируют пакеты с такими именами (slopsquatting). Модули Go привязаны к URL репозитория и проверяются по go.sum. Сборка — один статический бинарник.
USENIX Security 2025

Слабые места Go для агентов: многословность (больше кода и токенов) и гонки данных. 41% гонок в Go-коде Uber — захват переменной по ссылке в горутине, компилятор их не ловит (PLDI 2022).

14

Почему Python удобнее для MVP

На этапе MVP скорость изменений и простота отладки важнее размера образа и задержек. Здесь Python выигрывает.

Читаемый и короткий код

Нет if err != nil после каждого вызова и ручного маппинга строк в структуры. В нашем эксперименте реализация на Python на 27% короче при том же функционале. Код легче читать на ревью, в том числе не-разработчикам: аналитикам, продакт-менеджерам.

Интерпретатор прямо в контейнере

В Python-образе есть интерпретатор и shell. Можно выполнить любой скрипт или открыть REPL без пересборки: docker compose exec app python -c "…", разовая миграция данных, починка записи, выгрузка CSV. Go-образ (distroless) не содержит даже shell: проверку healthcheck пришлось встроить в сам бинарник, а любой новый скрипт требует пересборки образа.

Быстрый цикл правок

Нет шага компиляции: правка → uvicorn --reload → результат за секунды. Скрипты seed, админки и отладки пишутся на том же языке, без отдельного cmd/ и сборки.

OpenAPI и валидация из коробки

FastAPI и Pydantic генерируют Swagger из кода. Python-агент получил спецификацию автоматически и добавил тест на расхождения. Go-агент написал 651 строку YAML вручную.

Экосистема для данных и AI

pandas, numpy, SDK всех LLM-провайдеров, Jupyter для исследования данных. По GitHub Octoverse 2025, на Python почти половина новых AI-репозиториев (582 тыс.). Если MVP завтра понадобится аналитика или LLM-функция, она добавляется без второго языка.

Проще найти людей и помощь

Python входит в двойку самых популярных языков на GitHub (+850 тыс. контрибьюторов за год). На него больше обучающих данных у моделей, поэтому агенты увереннее пишут на нём новый код.

Когда переходить на Go: MVP подтвердился и упёрся в производительность, память, размер образа или число сервисов. Тогда горячие пути переписывают на Go, а Python остаётся для админки, скриптов и аналитики.

Выводы

1. Язык почти не влияет на результат

Итоговые оценки 8,0 и 7,8, архитектура совпадает. Решающий фактор — модель и ТЗ, а не язык.

2. Go быстрее, Python дешевле

Большой сервис: Go закончил на 13% быстрее, Python потратил на 30% меньше токенов. Код на Go на 27% длиннее, в мини-задачах — на 53%.

2а. Мелкие скрипты — за Python

В задачах с готовыми библиотеками (Excel, графики) Python в 3 раза быстрее и дешевле при одинаковом качестве. В сервисных задачах (рассылка) разницы нет, а в regexp-фильтре Go даже чуть точнее.

3. У Go — артефакт эксплуатации

Образ 16 МБ против 255 МБ, COPY-загрузка seed в 1,8 раза быстрее, ниже медианная задержка. Это плюсы рантайма, а не агента.

4. Python лучше в тестах и проверке типов

Покрытие 97%, mypy --strict, OpenAPI генерируется из кода с тестом на расхождения.

5. Ревью обязательно

Оба агента отчитались «всё зелёное», но ревьюеры за 5–6 минут нашли воспроизводимые баги, приводящие к 500/400.

6. ТЗ на 10 млрд — с оговорками

Поиск средствами одного PostgreSQL на таком объёме не масштабируется. Оба агента вынесли решение в документацию.
