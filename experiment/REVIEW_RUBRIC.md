# Рубрика оценки качества (одинаковая для обеих реализаций)

Каждый критерий оценивается по шкале 0–10 с обоснованием и ссылками на файлы `path:line`.

| # | Критерий | Вес | Что проверять |
|---|---|---|---|
| 1 | Соответствие ТЗ | 20% | Все эндпоинты, фильтры, сортировки, поиск, аудит, формат ответа/ошибок, артефакты (README, ARCHITECTURE, QUERY_PLANS, openapi.yaml) |
| 2 | Масштабируемость БД | 20% | Партиционирование, индексы под реальные запросы, keyset без OFFSET, отсутствие COUNT(*), уникальность ISBN, путь к шардингу |
| 3 | Корректность | 15% | Баги в пагинации/курсорах, SQL, транзакциях, optimistic locking, soft delete, аудите; SQL-инъекции |
| 4 | Тесты | 15% | Реально проходят? Покрытие, интеграционные на настоящем PG, полнота сценариев |
| 5 | Качество кода | 10% | Структура слоёв, читаемость, обработка ошибок, отсутствие глобального состояния, линтеры |
| 6 | Эксплуатация | 10% | Docker (multi-stage, non-root, размер образа), compose, Makefile, конфиг, health/metrics, логи |
| 7 | OpenAPI | 10% | Полнота и соответствие реальному поведению API |

Итог: взвешенная оценка 0–10 и список топ-5 проблем по критичности.
